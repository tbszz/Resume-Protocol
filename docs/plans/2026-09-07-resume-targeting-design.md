# Resume Protocol 岗位证据化重构设计

## 目标

把产品从“生成一份看起来像简历的文本”升级为“针对某个 JD 选择证据、改写项目、再反向生成面试复习路线”的闭环工具。单一页面任务是：让求职者能解释为什么保留某个项目、改写了什么、面试官可能继续追问什么。

## 方案取舍

采用渐进式重构：保留 React + Vite + Express 和现有本地解析、岗位雷达、Boss dry-run 能力，在现有数据结构上增加 `projectStrategy` 与 `interviewPlan`。不迁移到 Next.js/Tailwind/GSAP，因为迁移会扩大风险，却不会直接提高简历质量；动效由 CSS 与少量 React 状态完成。

## 信息架构

```text
┌──────────────────────────────────────────────────────────────┐
│ 固定导航：品牌 / 流程 / 岗位雷达 / 简历 / 面试作战室         │
├──────────────────────────────────────────────────────────────┤
│ HERO：把经历写成岗位证据 + 当前目标岗位切换                  │
│       JD 关键词证据带（视觉签名）                            │
├──────────────┬───────────────────────────────────────────────┤
│ 任务进度轨   │ 01 材料 → 02 画像 → 03 岗位 → 04 模板         │
│ sticky       │ 05 正式简历 → 06 岗位证据 → 07/08 投递        │
├──────────────┴───────────────────────────────────────────────┤
│ 岗位证据：入选理由 / 命中关键词 / 项目 bullet / 面试追问      │
│ 面试作战室：技术主题 / STAR 故事 / 7 天复习路线               │
└──────────────────────────────────────────────────────────────┘
```

## 视觉系统

- Color：Paper `#F5F3EF`、Ink `#0A0A0A`、Fog `#E7E4DD`、Signal `#FF4D00`、Muted `#77756F`。
- Type：展示字使用 Arial Narrow / DIN Condensed 系列回退；正文使用 system-ui / Microsoft YaHei；数据标签使用 IBM Plex Mono / Consolas 回退。
- Layout：大字号杂志式 Hero，内容区采用 12 列栅格和细线分隔；圆角只用于可点击的岗位胶囊，其余保持精确直角。
- Signature：一条横向“岗位证据带”，持续展示目标岗位、JD 词、命中证据和待补缺口；它既是动态视觉，也是真实产品信息。
- Motion：只保留首屏文字切换、证据带滚动与按钮磁性位移；尊重 `prefers-reduced-motion`。

## 数据流与可信边界

原始项目先按 JD 和岗位关键词评分，再按相关性排序。项目 bullet 只重排原文中已有分句和关键词，不创造数字、职责或结果。每条策略同时保留原文、命中词和面试追问，用户可追溯改写依据。正式简历使用岗位化 bullet，而不是重新回退到原始项目段落。

面试计划由目标岗位、命中技能、缺口和入选项目生成：技术主题回答“复习什么”，项目追问回答“如何自证”，7 天路线回答“何时练”。API 调用失败时沿用现有错误事件机制；缺少项目时返回明确的补充提示，不生成虚构内容。

## 验证

- 单元测试覆盖项目排序、非虚构改写、不同岗位输出差异、面试计划结构。
- 现有岗位源测试不得回归。
- 生产构建必须通过。
- 浏览器验证桌面与移动布局、键盘焦点、动效降级、岗位证据与面试模块可见。
